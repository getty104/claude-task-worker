# 調査・再分析の成果物

前提の可否を確定させる調査Issueの成果物と、既存Issueを再分析して description を書き直すときの扱い。

## 調査結果は実測を正とし、測定不能・未実測を明記して残す

**適用条件**: 外部ツール・外部サービスの挙動に依存する前提を確定させる調査タスクを起票・実施するとき

成果物は `docs/` 配下の実測メモとし、実測日・対象ツールのバージョン・結論表・再現手順・未実測項目・実測の副作用を含める。実測できなかった項目は推測で埋めず「測定不能」と理由を書き、判定を空欄にもしない。実測結果が事前の設計文書や依頼本文と食い違った場合は実測を正とし、設計文書側を追随させ、前提が崩れた分岐は実装しない。理由は、推測で埋めた可否は後続の実装がそのまま前提として消費し、誤りが実装完了後にしか現れないため。

出典: #223, #226, #232

## 依頼本文の誤りは訂正して残し、スコープは依頼どおりに保つ

**適用条件**: 既存Issueの再分析で、依頼本文が挙げる参照先・行番号・症状・手段が現状と食い違うと判明したとき

食い違いは黙って読み替えず、何がどう違うかを description の参照情報へ明記する。訂正するのは事実の記述だけで、依頼が定めた要件・スコープは動かさない（誤った前提から導かれた分岐は、前提が崩れたことを記したうえで実装しない）。理由は、誤った参照先を残すと後続の実装が存在しない根拠を探して止まり、逆に黙って読み替えると依頼者が誤りに気づけないため。

出典: #353, #355, #354
