# E2Eテストの取り扱い

`exec-issue` / `fix-review-point` が、対象プロジェクトのE2Eテストを完了条件に含めるかを決めるときに読む。

## 判定（タスク分解の後、サブエージェント起動前に一度だけ）

次のいずれかに該当すればE2Eテストが「ある」とみなし、所在と実行コマンドを控えて後続フェーズで使い回す。

- E2Eフレームワークの設定ファイルがある（`playwright.config.*` / `cypress.config.*` / `wdio.conf.*` / `nightwatch.conf.*` など）
- `e2e/` / `tests/e2e/` / `cypress/` などのE2Eテスト用ディレクトリがある
- `package.json` の `scripts` に `test:e2e` / `e2e` 等の実行コマンドがある

## ある場合

変更がユーザー操作フロー（画面遷移・フォーム入力・API連携・CLIの入出力など、既存E2Eテストが検証している境界）に影響するなら、

- そのタスクの完了条件に「該当フローのE2Eテストの追加・更新」を含める
- ブリーフィングにE2Eテストの所在・実行コマンド・既存テストの書き方の参照先を含める
- テストとLintの収束ループでE2Eテストも実行する

ユニットテストが通っただけで完了扱いにしない（ユーザー操作フローの回帰はユニットテストでは捕まらないため）。

## ない場合

Issue・指摘が明示的に求めない限り、E2Eテスト基盤を新規に導入しない（スコープ外の変更になるため）。
